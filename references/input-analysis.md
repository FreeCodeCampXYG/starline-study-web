# 输入分析规则

## TXT

1. 使用 `extract_local_sources.py` 读取，并保留行号区间。
2. 忽略孤立空白，但不要提前删除标题、列表、代码块或表格文本。
3. 编码依次尝试 UTF-8 BOM、UTF-8、GB18030、UTF-16；在 source packet 记录最终编码。
4. 超长文本按自然段和长度分块，后续摘要仍引用原始行号。

## PPT/PPTX

1. `.pptx` 是 ZIP/XML，可由脚本按 `slide 1..N` 提取文本并导出 `ppt/media/` 素材。
2. 幻灯片顺序是叙事线索，不等于所有 bullet 都同等重要。识别标题、论点、例子、数据和结论。
3. PPT 内图片只有在与相邻页面知识点相关时复用；无法确定含义时不要自动装饰。
4. `.ppt` 为旧二进制格式。没有 LibreOffice/PowerPoint 转换能力时应 fail loud，请用户另存为 `.pptx`。
5. 仅有图片的幻灯片需要 OCR/视觉分析；若环境不具备能力，记录 `missing evidence`。

## 视频链接

按以下证据优先级读取：

1. 用户提供的字幕/讲稿；
2. 平台公开字幕，保留时间戳；
3. 视频页面公开正文、章节和作者描述；
4. 标题、缩略图和少量元数据，仅能做资料登记，不能当作完整内容。

不得绕过登录、付费墙、地区限制、DRM 或 robots/平台限制。不得把评论区观点当作视频作者观点。自动字幕可能错词，专业术语应与 PPT/TXT 或权威拼写交叉核对；无法核对时保留不确定标记。

## 多来源综合

先生成逐来源摘要，再建立“主张—证据矩阵”：

| 主张 | 来源定位 | 类型 | 置信说明 |
|---|---|---|---|
| 原材料明确陈述 | `[S1:slide 4]` | 来源事实 | 直接证据 |
| 从两个段落归纳 | `[S1:slide 4] [S2:lines 20-35]` | 推断 | 标明“综合来看” |
| 为学习者补充的做法 | 无 | 学习建议 | 不伪装为来源原话 |

冲突时保留各自说法和定位；不要用平均化语言抹掉差异。
