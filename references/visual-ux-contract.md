# 交互与体验契约

## 渲染前体验定义门禁

视觉与内容结构不是流水线末端的包装。开始提炼章节、选主题或渲染 HTML 前，必须按 [渲染前体验简报](experience-brief.md) 写出 `experience-brief.md`。没有可验证的首要任务、10 秒成功标准、唯一主行动、移动端首屏目标和渐进披露清单时，不得继续。实质设计任务的 Apple、Kimi 与可信设计 Skill 研究也在此阶段完成；生成后阶段只负责回归，不负责第一次发现方向。

## 信息架构

先识别用户要完成的工作：判断资料价值、按真实任务进入、掌握核心模型、找回原始证据。采用任务导向的渐进披露：快速开始 → 任务路线 → 核心阅读线 → 完整证据库。资料目录和标签属于辅助导航，不得成为首屏理解前提。

## 学习状态

- 长文档提供可见阅读进度、继续上次、已读和收藏；状态默认只保存在本地浏览器。
- 核心 20% 必须形成有顺序、可完成的阅读线，不能只是一组无状态摘要卡片。
- 搜索之外至少提供按真实任务进入的路线，避免要求用户先记住资料术语。
- 用户可清除筛选、重置状态和退出任务路线，保持控制权。

## 必备交互

- 搜索范围覆盖页码、标题、章节、标签和批注。
- 筛选器至少支持全部、核心20%、行动项、案例；选中状态不能只靠颜色表达。
- 页面卡片显示页码、章节、标题和少量标签；点击或键盘 Enter/Space 打开原页预览。
- 弹层具备可访问名称、明确关闭按钮、Escape 关闭和可见焦点。
- 原页弹层支持前后翻页；长序列建议支持键盘方向键、已读和收藏。
- 尊重 `prefers-reduced-motion`；移动端不得依赖 hover。

## 弹层实现与回归

- 关闭弹层只保留一条底层关闭路径。若封装 `closeModal()`，它最终必须调用浏览器原生 `dialog.close()` 或等价状态更新，禁止调用自身；避免用全局文本替换把原生关闭调用改成包装函数而形成递归。
- 修改弹层后至少在真实浏览器依次验证：打开、关闭按钮、Escape、点击遮罩、上一页和下一页。每次重新打开仍应正常，控制台不得出现 `Maximum call stack size exceeded` 等页面自身异常。
- 自动化测试必须真正点击交互控件并断言弹层状态变化，不能只检查函数名、DOM 节点存在或页面能够加载。
- 控制台报错按来源归类：项目脚本（如 `app.js`）属于页面缺陷；`content_main.js` 等扩展注入脚本通常来自浏览器扩展。使用无痕窗口或禁用扩展复核后再归因，不能用扩展报错掩盖页面错误，也不能为消除扩展自身错误而修改网页业务代码。

## 视觉原则

- 使用清晰的字号层级、有限色彩和稳定间距，不堆叠无意义装饰。
- 标签是定位控件，不是彩色徽章墙；同类标签保持颜色与语义一致。
- 图片必须有描述性 alt；原页缩略图使用懒加载，并保留 16:9 或原始比例。
- 交付前用真实浏览器检查桌面与窄屏。窄屏必须使用设备视口模拟并比较 `scrollWidth` 与 `clientWidth`；Windows 无头窗口可能受最小窗口宽度影响，单纯裁剪截图不能证明响应式正确。
- 至少验证一条任务路线、原页弹层、阅读进度刷新后保留和收藏筛选。若无法运行交互验证，报告 `missing evidence`。
- 弹层验收应覆盖按钮关闭、Escape 和遮罩关闭；涉及页面切换时同时覆盖前后翻页，并确认控制台没有页面脚本未捕获异常。

## 体验简报回归门禁

首版 HTML 能打开不等于适合人使用。完成首版渲染后、最终浏览器验收前，必须逐项对照 `experience-brief.md`。这个阶段不增加无关功能，也不第一次决定用户任务或设计风格；只修正实现偏离、选择负担和操作成本。

### 1. 从第一性原则重新审视页面

先回答并记录以下问题，再动视觉样式：

1. 谁会在什么场景打开这个页面，是第一次学习、快速复习，还是查找证据？
2. 用户进入后的前 10 秒最可能完成什么？首屏是否让这个动作显而易见？
3. 页面是否只有一个主行动；其余入口是否按频率和重要性降级？
4. 首屏主要面积是否给了学习内容、当前进度或搜索，而不是品牌口号、主题选择器、装饰统计或设置？
5. “按目标浏览”和“已知内容搜索”两条路径是否都短且可逆？
6. 点击前是否已经能判断标题、核心结论、来源定位、预计阅读量和学习状态？

不得以“更好看”作为唯一优化理由。每一项修改必须对应一个具体问题，例如选择过多、层级不清、正文过窄、卡片密度过高、反馈不可见、移动端难点按或证据入口太深。

### 2. 外部先例研究

- 对实质性设计或用户明确要求高质量体验的任务，在网络可用且无需泄露私有材料时，优先核对当前 Apple 官方设计指南、Kimi 当前公开界面，再查看 1–3 个与信息架构、可访问性或学习型界面直接相关的可信设计 Skill 或维护活跃的开源先例。
- 官方指南和实际产品界面优先于二手截图、风格聚合站和营销稿。记录检索日期、链接、适用问题以及 `keep / adapt / reject`，不得把安装量、Star 数或流行度写成用户体验质量的证明。
- 阅读外部 Skill 只提取可验证的原则；未经审查不得安装、执行远程脚本或向其上传客户资料。
- 无网络时使用本契约继续优化，并标记 `missing evidence: current external design references not checked`。不得凭记忆描述当前产品界面。

### 3. Apple 与 Kimi 设计视角的转译

Apple 视角用于校准：清晰的视觉层级、内容优先、熟悉且一致的控件、自适应布局、可见状态、可访问性，以及克制而有意义的动效。

Kimi 视角用于校准：安静的工作画布、一个突出的当前任务、稳定可见的高频导航与搜索、清楚的输入/反馈关系，以及对低频工具的渐进披露。

这是评价镜头，不是风格名称。禁止复制 Logo、品牌字样、商业外观、专有图标、精确配色或逐像素布局；也不得为了“像 Apple/Kimi”牺牲来源追溯、可读性或用户自己的品牌语境。

### 4. 生成后优化动作

- 用真实使用频率重新排序。开始/继续学习、搜索、核心路线和证据回溯优先；主题选择、导入导出、来源权利说明、全部标签和高级筛选不得占据首屏主视觉，除非它们正是当前任务或关键证据限制。
- 遵循“一屏一个主要决定”。主按钮最多一个；次级动作降低对比度或放入局部工具区，危险或不可逆动作必须与普通动作分离。
- 文本密集型笔记默认优先列表、目录和阅读线；只有内容需要视觉比较或图片识别时才使用大卡片。避免卡片套卡片、彩色徽章墙、超大 Hero 和无助于决策的装饰统计。
- 信息由近及远：标题旁给结论与状态，段落旁给来源定位，深入解释与完整权利信息可展开，但证据不足、授权风险等关键限制不得藏进默认折叠区。
- 反馈必须即时且准确。计数、筛选结果和进度首次渲染即显示最终真实值；不得用从 0 开始的数字动画制造短暂错误状态。保存、清除筛选、复制链接等操作要给可见结果。
- 移动端不得依赖 hover；常用触控目标建议至少 44×44 CSS px，正文无需横向滚动，固定栏不能遮挡内容，键盘焦点顺序与视觉顺序一致。
- 动效只表达层级、状态和空间关系；尊重 `prefers-reduced-motion`，不使用持续漂浮、无意义视差或阻碍阅读的入场动画。

### 5. 前后对照与放行

优化前列出 3–6 个影响最大的可用性问题，优化后逐项说明改动及其服务的用户任务。至少在桌面和窄屏真实设备视口复核首屏、主路线、搜索/筛选、证据回溯、键盘焦点和弹层关闭路径，并比较 `scrollWidth <= clientWidth`。若无法完成真人可用性测试、跨浏览器测试或外部先例核对，分别标记 `missing evidence`，不能用主观审美评价替代验证。
