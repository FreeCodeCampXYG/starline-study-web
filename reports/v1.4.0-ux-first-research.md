# v1.4.0 · UX-first redesign evidence

- Researched at: 2026-08-14
- Problem: UX decisions existed in v1.3.0 but appeared after source extraction and again after first render, so generic structure could harden before user-task analysis.
- Queries: `learning note web UX`, `study guide information architecture`, `accessible responsive web design`

## Keep / adapt / reject

| Source | Lesson | Decision |
|---|---|---|
| Apple Human Interface Guidelines | Clear hierarchy, content focus, familiar controls, visible state, adaptation and accessibility must be behavioral requirements. | Adapt into ten-second success, one primary action, responsive and accessibility gates; never imitate Apple trade dress. |
| Kimi official public interface | Long-form knowledge work benefits from a quiet workspace, prominent current task, stable search/navigation and progressive disclosure. | Adapt as a task-and-reading lens; no logo, exact palette or pixel copying. |
| `addyosmani/agent-skills: frontend-ui-engineering` | Read the existing system first; reject generic hero, stock card grids, excessive gradients, padding and shadows; test real mobile widths. | Keep anti-generic and responsive verification; adapt to standalone learning HTML. |
| `microsoft/vscode: accessibility` | Keyboard reachability, visible focus, Escape dismissal, state announcements and focus restoration are implementation requirements. | Keep interaction checks; reject VS Code-specific help-provider architecture as out of scope. |
| `nexu-io/open-design: hallmark` | Structural variety matters more than recoloring a template; preflight and explicit anti-pattern review reduce AI-default layouts. | Adapt pre-render structure audit and anti-pattern list; reject theme rotation, mandatory token exports and marketing-page machinery. |

## Rejected candidates

SkillsMP results for continuous learning, posters, SNMP, authentication and video remix were keyword collisions. Repository stars were treated only as discovery metadata, not UX quality evidence.

## Original contribution

`experience-brief.md` is now a blocking, pre-render product contract joining source-grounded learning goals with ten-second success, one primary action, evidence return and a 390×844 first-screen target. Post-generation UX work becomes regression against that contract instead of the first moment user experience is considered.

## Missing evidence

- Skills.sh discovery did not run on Windows because the research tool looked for `npx` rather than `npx.cmd`; SkillsMP and direct GitHub source review were used instead.
- Current external sources were inspected as public principles, but no human blind review, learner task-completion study or provider-backed A/B run has been completed.
